# PPO 交通违章表单自动填表插件 (مساعد مخالفات المرور)

专为埃及公诉机关交通门户 (`https://www.ppo.gov.eg/ppo/r/ppoportal/ppoportal/traffic`) 定制的现代化 Chrome 插件。支持多车辆配置管理、阿拉伯字母快捷输入、智能双模护照容错重试、生效格式自学习记忆、精准官方异常诊断、实时罚款数据抓取与结果卡片展示，以及**完整的历史查询记录大窗口中心**。

## 🚀 核心功能特点

### 1. 🔄 智能双模护照格式自动容错重试 (Dual-Mode Auto-Retry)
- **痛点解决**：埃及交警车辆库中，部分车辆登记的是**纯数字护照**（如 `2891946`），部分车辆登记的是**带前缀字母原版**（如 `EF2891946`）。
- **双模自动接力**：
  - 首轮查询若触发官方证件不匹配报错（`الرقم القومي أو رقم الرخصة غير صحيح`），插件在 **500毫秒内** 自动关闭官方弹窗；
  - 自动无缝切换为备选格式（纯数字 ⇄ 带字母原版）重新提交；
  - 单次查询严格限制 1 次自动切换，成功即止，杜绝死循环。

### 2. 🧠 成功查询配置智能自学习与格式记忆 (Auto-Learning & Retention)
- **生效格式自动记忆**：查询成功后，系统自动捕获官方真正生效的护照号码与模式（`passportFormat: 'raw'` / `'cleaned'`）；
- **常用库自动同步**：自动将最新生效格式更新至常用车辆库（`ppo_traffic_profiles_v2`），新车自动建档；
- **下次直达最优解**：下次查询该车时直接以成功过的格式一次性提交，实现 **0 试错、毫秒级一次命中**。

### 3. 🏷️ 全界面显式格式标识体系
- **下拉菜单**：清晰标注 `👤 EF2891946 (3184) [🔤带字母]` / `[🔢纯数字]` / `[🆔身份证]`；
- **输入提示条**：实时高亮显示 `🏷️ 护照提交格式: 🔤 完整原版 [EF2891946] (查询将直接以此格式一次性命中)`；
- **历史记录中心**：表格与卡片均带有 `🔤 带字母原版` / `🔢 纯数字` 独立徽章；
- **配置中心抽屉**：每辆车的记忆绑定格式一目了然。

### 4. 🚨 官方异常精准中文诊断与排查报告
- **官方会话超时**（`لقد انتهت جلستك برجاء إعادة تحميل الصفحة`）：识别黄色警示条，提示 `⏱️ 官方会话已超时过期` 并提供自愈指引；
- **车牌与证件不匹配**（`الرقم القومي أو رقم الرخصة غير صحيح، يرجى التحقق`）：自动识别红色弹窗，提示 `❌ 车牌号或证件号不匹配/不正确` 并自动解卡；
- **完整失败报告入库**：发生错误时自动以 `⚠️ 出错` 归档，点击详情可查看结构化原因剖析、排查建议与精准毫秒耗时。

### 5. 📜 完整历史查询记录大窗口中心 (`history.html`)
- **全量自动留存**：每次查询自动记录车牌、字母、护照号、国籍、总罚款、违章笔数、和解金、原始请求 JSON 与原始响应文本快照；
- **可视化数据仪表盘**：实时统计总查询次数、累计罚款总额、累计违章笔数与已查车辆数；
- **搜索与多维过滤**：支持多关键字即时搜索，支持按罚款状态（有违章/无违章/出错）过滤与排序；
- **双视图切换与导出**：大屏表格视图与卡片流视图，支持一键导出 Excel/CSV/JSON，支持「一键再次填表查询」。

## 🛠️ 关键技术踩坑与避坑指南 (Engineering & Architecture Insights)

针对埃及公诉机关门户网站的 **Oracle APEX 20+** 架构与 **F5 BIG-IP WAF** 防火墙体系，在研发过程中攻克并总结了以下 9 大关键核心坑点：

### 1. F5 BIG-IP WAF 硬件防火墙的指纹阻断机制
- **❌ 踩坑现象**：直接通过后台纯 HTTP 请求（如 Service Worker `fetch`）发包，或无差别删除所有 Cookie 后发起请求，会被官方直接阻断（返回 `Request Rejected / Support ID: xxxx`）。
- **🔍 根本原因**：官方前置了 F5 BIG-IP WAF 硬件防火墙。纯 HTTP 请求缺少合法的 TLS Session Affinity、`Sec-Fetch-Dest: document` 标头以及动态签发的 `TS01xxxxxx` / `BIGipServer...` 加密安全凭据。
- **✅ 避坑方案**：
  1. 默认采用稳定可靠的真实浏览器渲染通道；
  2. 在进行环境清理时，**严格保留 `TS...` 和 `BIGipServer...` 等 WAF 硬件信任令牌**，仅清理冲突的 APEX 业务会话，防止被防火墙误判为可疑篡改。

### 2. Oracle APEX 裸 URL 导航报错 (`?clear=201,14,RP`)
- **❌ 踩坑现象**：在已有标签页上通过拼接 `?clear=201,14,RP` 试图重置表单时，官方页面提示 `لا يمكن الوصول إلى هذه الصفحة (无法访问此页面)`。
- **🔍 根本原因**：APEX 框架的 `?clear=` 重置指令依赖当前请求中包含有效的 `p_instance` 会话上下文，裸带参数跳转会触发 APEX 会话校验失败。
- **✅ 避坑方案**：
  统一使用干净的标准入口 `https://www.ppo.gov.eg/ppo/r/ppoportal/ppoportal/traffic` 进行导航或刷新，交由 APEX 自身优雅初始化。

### 3. DOM 监听器的“强制同步重排死锁 (Forced Reflow / Black Screen)”
- **❌ 踩坑现象**：页面偶尔出现纯黑屏、无法渲染或卡死并触发 25s 超时。
- **🔍 根本原因**：`MutationObserver` 监听 `document.body` 时未做防抖，且在回调中读取了 `document.body.innerText` 并遍历了成千上万个 `div, span, td`。在 APEX 异步加载组件时，瞬间触发数百次全页面强制同步重排（Reflow），导致 Chrome 渲染进程打满死锁。
- **✅ 避坑方案**：
  1. 为 `MutationObserver` 增加 500ms 防抖；
  2. 在普通表单阶段加入“快速放行”网关，非结果摘要页严禁执行全量 DOM 扫描和 `innerText` 计算。

### 4. 插件悬浮窗 DOM “自抓取死循环 (Self-Scraping Loop)”
- **❌ 踩坑现象**：历史记录中心每隔十几秒自动新增一条相同记录，且绿色提示条不停闪烁，快照内容包含插件自身的文本。
- **🔍 根本原因**：插件自身的悬浮窗中也包含阿拉伯语词汇（如 `عدد المخالفات` 违章笔数）。脚本在全局扫描页面时，误将插件悬浮窗自己的卡片识别为官方结果，形成了“扫描自身 -> 存入历史 -> DOM 变动 -> 再次扫描自身”的死循环。
- **✅ 避坑方案**：
  1. 抓取与快照严格排除 `:not(#ppo-autofill-container):not(#ppo-toggle-bubble)`，仅扫描官方容器（`.t-Region`, `.t-Body-main`）；
  2. 增加结果指纹去重（`lastCapturedSign`）与防重入锁。

### 5. 过早清理遮罩打断 APEX 异步组件初始化
- **❌ 踩坑现象**：页面第二次打开时，单选框联动与输入框交互彻底失效。
- **🔍 根本原因**：APEX 初始化时会挂载加载状态并异步执行 jQuery 依赖注入。若脚本通过定时器强行移除遮罩并重置 `disabled`，会打断官方脚本执行，引发底层 `TypeError`。
- **✅ 避坑方案**：
  完全移除启动时的自动解卡定时器，保持零干扰被动等待；自愈解卡仅在用户手动点击 `[🛠️ 自愈]` 时按需触发。

### 6. 多入口调度逻辑不一致
- **❌ 踩坑现象**：从弹窗点击正常，但在历史记录中点击「填表」会报错。
- **🔍 根本原因**：历史页面私自维护了一套独立的标签页查找与跳转代码，当已有标签停留在结果页时未能正确重置。
- **✅ 避坑方案**：
  将历史记录、配置管理与 Popup 的所有填表指令统一收敛到 `background.js`（`open_and_fill`），保证单点维护、100% 统一行为。

### 7. Oracle APEX 单选框在 Chrome 独立隔离环境下的事件穿透失效
- **❌ 踩坑现象**：填表时官方单选框依然停留在 `رقم قومي`（身份证），未能切到 `جواز سفر`（护照），导致官方以空身份证提交报错。
- **🔍 根本原因**：Content Script 运行在 Chrome 隔离上下文，`window.apex` 无法直接在脚本中调用；单纯修改 `radio.checked = true` 无法触发 APEX jQuery UI 内部绑定的动态联动逻辑。
- **✅ 避坑方案**：
  采用原生阿拉伯语 `<label for="...">` 文本做**深度穿透点击**（触发 `label.click()` 和 `radio.click()`），并增加 250ms 异步强化回填保障，确保官方护照输入框展示后值不丢失。

### 8. Oracle APEX 表单整页 POST 刷新导致 JavaScript 内存状态丢失
- **❌ 踩坑现象**：官方提交时会触发 HTTP POST 全页刷新，页面刷新后所有 in-memory 变量（`isAwaitingQueryResult`, `hasRetriedPassportAlternative`）重置为 `false`，导致容错重试被跳过。
- **🔍 根本原因**：整页刷新销毁并重新初始化了前端运行环境。
- **✅ 避坑方案**：
  引入 `sessionStorage` 跨页面刷新生命周期持久化（`ppo_is_awaiting_query`, `ppo_retry_count`, `ppo_active_query_req`），并在 `initApp` 启动时自动恢复状态；报错弹窗设立绝对优先捕获网关。

### 9. 历史记录去重机制误杀连续失败/测试记录
- **❌ 踩坑现象**：连续测试失败时，部分错误记录未保存到历史记录中心。
- **🔍 根本原因**：失败记录罚款和笔数均为 0，之前的粗粒度去重拦截误将其判定为重复结果。
- **✅ 避坑方案**：
  为 `error` 报错开辟独立 3 秒超短防抖通道，严格区分 `status` 状态，确保每一次真实测试失败均能完整入库并生成排查报告。

## 📦 安装与打包发布指南

### 本地开发者安装：
1. 浏览器打开 `chrome://extensions/`；
2. 开启右上角 **开发者模式**；
3. 点击 **加载已解压的扩展程序**，选择本项目根目录。

### 生成应用商店发布包：
在项目根目录下运行一键打包脚本：
```bash
./package_extension.sh
```
该脚本将自动完成全量 JavaScript 语法校验、静态文件打包，并在 `dist/` 目录下生成 `ppo-traffic-autofill-v1.0.0.zip`，可直接上传至 **Chrome Web Store** 或 **Microsoft Edge Add-ons** 开发者控制台。
